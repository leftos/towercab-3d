# Model converter review (owner request, 2026-10-21) — condensed

Three read-only reviews (oracle): Python converter, Rust msfs.rs, TS services. Present to the owner ranked, with options, and book what they accept (Linear adds). Booked already: TC3D-256 (texture-dir argv too long), TC3D-127 (remote browsers draw built-ins).

## Python converter (`scripts/shipping/conversion/convert_fsltl_batch.py`) — verdict: keep the GLB core, delete/rewrite the edges
Top 5:
1. bug :1295 (+ msfs.rs:1448): output file named after the raw livery title. 5 AIG titles end in `*` (Errno 22 after all textures decoded); 7 titles with `/` write into a subfolder the cache scan misses; `..\` would write outside the cache. Fix: caller passes a sanitized/hashed output path.
2. bug :1415/:1421: `--liveries`/`--texture-dirs` split on commas; 2 AIG titles contain commas → GLBs named after fragments, exit 0, Rust returns a missing path. Also the converter side of TC3D-256. Fix: `--job` JSON in, `--result` JSON out; resolve textures via the livery's `texture.cfg` `fallback.N` chain (only one folder needed).
3. bug :1595-1632 + msfs.rs:1465: real error goes to stdout, UI shows only "No models were successfully converted"; piped stdout uses the ANSI code page strictly, so a cp1252 en-dash title (U+FFFD after Rust's lossy decode) raises after the GLB is written → exit 1. Fix: UTF-8 stdout/stderr, errors via result JSON.
4. bug :830-836: GLB written in place; a kill leaves a truncated file whose JSON chunk (converterVersion) is intact, and msfs.rs:1496-1548 keeps it cached. Fix: write .tmp then os.replace.
5. perf :276-295 vs :629-654: every image decoded/resized/PNG-optimized/embedded though materials drop normal/emissive/occlusion/MR textures: 21 of 45 MB of image data in the 12 largest cached GLBs is unreferenced (measured). Fix: convert only images a material reaches.
Also: ~45% of the file (:845-1270, batch/progress in main) is dead or broken (Rust passes `--models-file`, argparse defines `--liveries-file`; `start_fsltl_conversion` lib.rs:561-695 has no caller); Python vs Rust decode cfg titles differently (errors='ignore' vs from_utf8_lossy) → remote "livery not found"; early stop :877 drops requested liveries (needs requested <= found); missing textures become magenta/grey placeholders silently; animation baking reads CUBICSPLINE in-tangent, misses q=(0,0,0,-1), picks keyframes per channel, last clip wins per node (latent/visual unconfirmed); only buffers[0] loaded; NORMAL dropped (faceted fuselage, design choice); every material forced OPAQUE (decals/glass); extensions stripped by hand in 9 places; image buffers mapped by position not index (latent); buffer/image URIs unchecked (`..`/absolute paths read any file, embedded in GLBs the host serves on the LAN); `convert_single_gltf` 608 lines, `main` 297; no tests (suggested pytest on synthetic glTFs + gltf-validator); deps unpinned, `pip install --upgrade` every build, build_converter.py:67-77 version print is a SyntaxError, `upx=True`; numpy only for float16 (struct 'e' suffices).

## TypeScript (`MSFSModelConversionService.ts`, `AircraftModelService.ts`) — verdict: keep and fix; rewrite conversion ownership (into Rust), matching (maps + pure matchModel with table test), index size
Top 5:
1. bug settings.rs:479 vs types/settings.ts:1139: Rust serializes `cacheLimitMb`, TS reads `cacheLimitMB`; the user's cache limit (incl. Unlimited) never survives a restart → LRU deletes models. Fix: `#[serde(rename = "cacheLimitMB")]`, FIELD_CLASSES path, fixture. (Also `.claude/agents/tauri-settings-bridge-reviewer.md:43` calls the field a String; it is Option<u32>.)
2. perf msfs.rs:1031-1034 → MSFS:252/656/702: each livery's `textureDirs` lists every texture folder of its aircraft folder: AIG index 10,082 liveries, 1,606,122 entries, 250 MB, parsed by the host WebView every launch and sent whole by `/api/msfs/index` to remote browsers (likely cause of TC3D-127, unconfirmed; same root as TC3D-256). Fix: only the livery's own folders; a path-free remote index.
3. perf AircraftModelService.ts:822: no-type aircraft with an airline callsign scan 12 types × 13,524 liveries before the cache check at :826, twice per aircraft per frame (useAircraftModels.ts:166, :290). Fix: cache first, cache misses, maps at index time.
4. bug AMS:509/723/924: cache key type+airline but step 2 matches by callsign → the first GA C172 decides every C172's livery; `findClosestModel` (MSFS:984) can pick any of 951 private (null-airline) liveries. Fix: per-callsign cache for registration matches; skip null-airline in closest search.
5. bug MSFS:1069-1084: in-progress recorded after an awaited disk check → two converters write the same GLB, size counted twice. Fix: record the promise synchronously.
Also: remote path decrements the concurrency counter twice (MSFS:1129-1131 + :1212-1217 vs :1282-1285); pending generic match reported finished (AMS:773); failures blocklisted for the session (never cleared); texture scale not in cache key; `clearCache` leaves dangling state → per-frame failing loads; LRU isn't LRU (timestamps only on AMS misses) and can evict on-screen models; `enforceLimit` not re-entrant; with no `cacheDirectory` (default null) nothing is reused across launches and remote routes 404 (MSFS:1139 vs :216/:1076); startup deletes models whose header couldn't be read; possible scale axis swap (wingspan factor on the fuselage, MSFS:890-896 / UAM:462-466; needs a visual check); lopsided size metric (0.65× passes, 1.4× fails); registration match exact-string (G-ABCD vs GABCD); stale index after a Community path change (MSFS:483-497), double indexing on enable (GSS:510-554 + PANEL:235-253); dead code, 7× duplicated priority loop, functions of 237/206/121 lines, relative imports, swallowed errors; CONVERTER_VERSION copied in TS/Rust/Python; `tests/model-matching.test.ts` re-implements matching and reads X:\Games (fails without it), included in vitest.config.ts:8.

## Rust (`src-tauri/src/msfs.rs`)
Verdict: keep, fix, and rewrite two parts as small tested functions: the indexer (cfg parser, list_models_unified, index cache; resolve model and textures per livery, follow texture.cfg fallbacks) and the converter runner (exists twice; one function managing the process and owning the output contract). No reachable panic, no command injection.
Top 5:
1. bug/perf :984-997, :1031-1035: every livery gets every sibling `texture.*` folder: 1,606,122 entries, aig_model_cache.json 250 MB, 2,347 liveries over 32,000 chars of argv (root of TC3D-256), ~3.2 s per launch; sibling folders also win over shared oci textures (latent). Fix: own folder + its texture.cfg fallback chain + shared oci/base; bump MODEL_CACHE_VERSION.
2. bug/risk :1424, :1751 (via server.rs:957): blocking `Command::output()` on the async runtime, no timeout, no kill on exit, no shared limit; host + remote can starve every runtime thread (HTTP, WebSockets, vNAS). Fix: tokio::process + kill_on_drop + timeout + job object (lib.rs:1030) + one shared semaphore/in-flight map.
3. bug :171-187: cfg keys matched by prefix, so `atc_id_enable`/`atc_id_color` overwrite `atc_id`: 3,406 of 3,442 FSLTL entries have atcId "1"/"0XFF000000", so registration matching never works for FSLTL; Windows-1252 files decoded as lossy UTF-8 garble titles/folders. Fix: exact keys; UTF-8 then Windows-1252.
4. bug :1384, :1448, :1724, :1762: unsanitized titles as filenames, comma-joined args, no check the output exists after exit 0 (2 comma titles, 10 with `/` or `*`, 263 texture folders with commas). Fix: Rust picks a sanitized output name, JSON job file, checks the file after exit.
5. bug :243-292: index cache invalidated only by the mtime of SimObjects/Airplanes; new liveries inside an existing AIGAIM folder never indexed (NTFS behaviour, not reproduced). Fix: per-folder fingerprints.
Also: glTF chosen per folder not per livery (71 of 331 AIG cfgs mix `model=` variants → wrong geometry); shared-model pick depends on folder order (why test_aig_crj200 fails: pick a deterministic tie-break or fix the test); index re-read per request (no in-memory index), written non-atomically (250 MB fs::write); converter path lookup ×3, invocation ×2 (remote copy omits --no-discovery); partial GLBs pass the cache scan (compare GLB header length with file size); `cargo` substring treats 32 main models as attachments (rescued today); swallowed errors (read_dir → empty, metadata → 0 skews LRU); dead `parse_aircraft_cfg_title`; println! timings never logged; list_models_unified ~400 lines. Tests: all 6 read X:\Games and silently pass without it; add fixture tests (parser BOM/cp1252/atc_id_enable/spacing, LOD priority, GLB reader, cache invalidation, arg building) and keep one #[ignore] smoke test. Security: `/api/msfs/index` and `/api/msfs/models` leak host-owned absolute paths (communityPath, cacheDirectory) to remotes; `POST /api/msfs/convert` unbounded (DoS from the LAN). Outside scope: server.rs:559 registers `/api/tower-positions/{icao}` but axum 0.7.9/matchit 0.7.3 uses `:icao`, so the remote PUT (tauriApi.ts:338) never matches (unverified at runtime).

## Cross-layer themes (for the owner)
1. One root cause behind TC3D-256, TC3D-127 and the slow launch: per-livery texture dirs list every sibling folder (fix in msfs.rs indexer + texture.cfg fallbacks).
2. The output contract between Rust and Python is fragile (titles as filenames, comma-joined args, exit code only, errors on stdout): replace with a JSON job/result file and sanitized names.
3. Conversion ownership is split (TS queue for the host, a second unthrottled Rust path for remotes, blocking on the async runtime): one Rust owner with a semaphore, in-flight map and LRU.
4. Quick wins: cacheLimitMB serde rename; exact cfg keys (fixes FSLTL registration matching); atomic GLB and index writes; per-callsign cache for registration matches.
5. Tests: none of the three layers has a real test; all existing ones read X:\Games.
