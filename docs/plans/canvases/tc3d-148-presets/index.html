Captures from the real app (feature branch feat/cesium-weather at 2042739), headless Edge against pnpm run vite:headless, KOAK tower camera, 13:00 local fixed time, 1596×800 canvas. Only the cost knobs change between lanes; the look knobs (densityScale, fogExtinction, fogHeightScale) are the same in every lane. Clouds drift with the wind, so cloud shapes move slightly between lanes of a row (each row was shot lane after lane within about a minute).

Read the clear-sky band (pale cyan strip between the deck edge and the terrain), the blockiness of cloud edges, and the softness of the far deck. The 2× crops under three rows are nearest-neighbour enlargements of the same capture.

How it was driven

  • Knobs: import('/constants/weather.ts') returns the same WEATHER_STAGE_QUALITY object the stage hook reads (not frozen; as const is type-only), so Object.assign on it changes steps and radius live. textureScale is read once at stage creation, so each lane change turned showClouds and showBabylonFog off and back on, which removes and recreates the stage; the new stage's get(0).textureScale was read back (0.5 / 0.375 / 0.25). No tracked file was edited.
  • Weather: setDebugOverriding(true), setCloudLayers with the debug panel's coverage values (BKN 0.6875, OVC 1.0, FEW 0.1875), currentMetar.visib set to 10 or 3, precipitation off, weather interpolation off. __tc3d.weatherStage.info().stageEnabled was true in every lane cell.
  • Camera: KOAK tower camera (followMode: tower, no tower mod loaded), set through __tc3d.camera.set. The aircraft panel and hints were hidden with a page style for the shots.
  • Lane D (Low with the look knobs also cut) was not shot: in cloudStage.glsl.ts the three look knobs only scale values inside the existing loops (the raymarch runs u_steps steps over the slab crossing, dt = (t1 - t0) / u_steps). The one way they touch cost is the march's early exit at transmittance 0.01, which a lower densityScale reaches later, so cutting it would cost more, not less.
